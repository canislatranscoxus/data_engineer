    Overview

    Welcome to your first batch data pipeline with Google Cloud's Dataflow job builder! This tool provides a user-friendly, form-based interface to build data processing jobs without writing complex code.

    In this introductory lab, you'll build a simple but powerful pipeline to process financial data. You'll configure the job to read a CSV file of loan applications from a Cloud Storage bucket, filter the data to isolate only the "Approved" loans for a report, and load the clean, filtered results into a new BigQuery table for analysis. This is a fundamental pattern for many data engineering tasks.

    Objectives

    In this lab, you'll learn how to:

    • Build a simple batch data pipeline using the Dataflow job builder UI.
    • Configure a pipeline to read CSV data from Cloud Storage.
    • Use the Filter (Python) transform with a simple one-line expression to select specific records.
    • Configure a sink to automatically create and write to a new BigQuery table.
    • Execute and monitor the Dataflow job and verify the results in BigQuery.

    Your lab environment

    When you begin this lab, a script runs to automatically provision the necessary infrastructure. The following have been created for you:

    • Project ID =
    • Region =
    • Two Cloud Storage buckets:
      1. An input bucket (gs://-input-bucket) to store the raw source data file.
      2. A staging bucket (gs://-staging-bucket). This location is a mandatory requirement for the Dataflow service to store temporary files.
    • A raw data file: A 1,000-record CSV file (source/loan_applications.csv) containing mock financial data has been uploaded to the input bucket.

    Task 1. Explore your environment

    First, confirm that your lab resources were created correctly and preview the source data.

    Confirm the Cloud Storage buckets

    1. In the Google Cloud Console, use the Navigation menu (☰) to go to Cloud Storage > Buckets.
    2. Confirm that you see two buckets listed, with suffixes -input-bucket and -staging-bucket.

    Preview the raw data and enable APIs

    1. Click the Activate Cloud Shell icon () in the top-right corner of the console.
    2. Run the following command to view the header and the first 5 records of the loan application data. gcloud storage cat gs://{{{project_0.project_id|Project_ID}}}-input-bucket/source/loan_applications.csv | head -n 6
    3. Run the following command in Cloud Shell to enable the Dataflow and BigQuery APIs: gcloud services enable dataflow.googleapis.com bigquery.googleapis.com
    4. Run the following commands in Cloud Shell to instantiate and authorize the Dataflow Service Agent permissions: # Generate Dataflow service identity account gcloud beta services identity create --service=dataflow.googleapis.com --project={{{project_0.project_id|Project_ID}}} # Wait for the account to propagate across IAM directory servers sleep 15 # Retrieve project identity details PROJECT_NUMBER=$(gcloud projects describe {{{project_0.project_id|Project_ID}}} --format="value(projectNumber)") # Assign necessary security roles gcloud projects add-iam-policy-binding {{{project_0.project_id|Project_ID}}} \ --member="serviceAccount:service-${PROJECT_NUMBER}@dataflow-service-producer-prod.iam.gserviceaccount.com" \ --role="roles/iam.serviceAccountUser"

    Task 2. Build and launch the Dataflow job

    Now you'll use the Dataflow job builder's form-based interface to configure and launch your first pipeline.

    1. In the Google Cloud Console, navigate to Dataflow > Jobs.
    2. Click + Create Job from Builder.

    Step 1: Configure Job Details and Source

    1. Job name: filter-approved-loans
    2. Job type: Select Batch.
    3. In the Sources section, fill out the New source form:
      • Source name: read_loan_applications
      • Source type: Select CSV from Cloud Storage.
      • Cloud Storage path: Click Browse. Navigate to and select the source file: gs://-input-bucket/source/loan_applications.csv.
      • Click Done.

    Step 2: Configure the Filter Transform

    This transform will inspect each row and only allow rows that match a specific condition to continue through the pipeline.

    1. In the Transforms section, click Add a transform.
    2. Fill out the new transform form:
      • Transform name: filter_for_approved
      • Transform type: From the dropdown, select Filter (Python).
      • In the Python expression text box, enter the following one-line expression to select only the rows where the status column is 'Approved': status == 'Approved'
      • Source: Ensure read_loan_applications is selected.
      • Click Done.

    Step 3: Configure the BigQuery Sink

    The sink is the final destination for your processed data. You'll configure it to create a new table in BigQuery for your filtered results.

    1. In the Sinks section, a default "New sink" form will be present. Configure it as follows:
      • Sink name: write_to_bigquery
      • Sink type: Select BigQuery Table.
      • Select Create new table.
      • Click Browse then click the project name.
      • Dataset: Create a new dataset by entering loan_data.
      • For Data location, select US (multiple regions in United States) (or your lab assigned region), then click Create dataset.
      • Table: Enter approved_loans.
      • Input step for the sink: From the dropdown, select filter_for_approved.
      • Click Done.

    Step 4: Configure Runtime Options and Run

    1. At the bottom of the page, expand the Dataflow Options section.

    2. Make sure the Regional endpoint is set to the lab specified region.

    3. For Temporary location, click Browse, navigate to your staging bucket (...-staging-bucket), and click Select.

    4. Scroll down to the Worker region field and set it to the lab specified region.

    5. Uncheck the Use default machine type checkbox.

    6. Under the machine configurations that appear, update the following:

      • Series: Select E2.
      • Machine type: Select e2-standard-2.

    7. Click Run job.

      [!NOTE] The total wait time for the job to complete is typically 5 to 10 minutes:

      • Queued / Starting: Usually takes 2–3 minutes to provision the Launcher and Worker VMs.
      • Running: Takes another 3–5 minutes to actually process the data and write it to BigQuery. Once the job finishes, the status will update to Succeeded!

    Click Check my progress to verify the task. Build and launch the Dataflow job

    Task 3. Monitor the Dataflow job

    1. You'll be taken to the Jobs page. Click on your filter_approved_loans job to view its details. You can monitor progress via the Job Logs and see job steps via a table view or graph view, as well as see the running logs as your pipeline runs.
    2. The job will take approximately 10 minutes to provision resources and process the data. Wait for the Job status to show Succeeded.

    Click Check my progress to verify the task. Monitor the Dataflow job

    Task 4. Verify the results in BigQuery

    Now, confirm that your filtered data landed in the correct BigQuery table.

    1. In the Google Cloud Console, navigate to BigQuery.
    2. In the Explorer panel, find your project, expand it, and you should see the new loan_data dataset. Expand the dataset to find the approved_loans table.
    3. Click the table name and then select the Query tab.
    4. Run the following query to count the filtered records: SELECT count(*) as total_records FROM `{{{project_0.project_id|Project_ID}}}.loan_data.approved_loans`; The count should be about 330 records.
    5. Next, run a query to view a sample of the data to confirm that all records have the 'Approved' status. SELECT * FROM `{{{project_0.project_id|Project_ID}}}.loan_data.approved_loans` LIMIT 10;

    Click Check my progress to verify the task. Verify the results in BigQuery

    You've successfully built and tested your first batch data pipeline using the Dataflow job builder!

    You used the form-based job builder UI to read a CSV file, apply a simple filter to isolate approved loan applications, and create a new BigQuery table with the results. This is a foundational skill for building more complex data processing solutions on Google Cloud.
