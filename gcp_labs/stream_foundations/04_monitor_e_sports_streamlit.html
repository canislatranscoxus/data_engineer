    GSP1343

    Overview

    Imagine you are a data engineer for Cymbal Gaming. You and the development team are building a new e-sports game, "Galactic Grand Prix." The game produces real-time data from heads-up matches between two players from different teams, where a winner is determined and points are awarded to the winning player and team. The game also supports in-game chat so that players can communicate with teammates. Although players are aware of the End User License Agreement, they may occasionally act unsportsmanlike, especially during intense matches, which is reflected in chat messages. You have been tasked with creating a solution for moderators to monitor and take action on chat messages that break the terms of the end user license agreement.

    You have explored Pub/Sub, BigQuery, Bigtable, and the Streamlit Framework (Python), identifying them as potential tools for this use case. You have also learned that Gemini can help you with the build. For example, if you get stuck with writing a new query you could use it for help. However, you are not sure how to get started.

    When you start the lab, the following resources and files are provided to you.

    By the end of the lab, you will have used the architecture to perform several tasks.

    The following table provides a detailed explanation of each task in relation to the lab architecture.

    Numbered Task Detail
    1. Configure environment variables in Cloud Shell.
    2. Create the Cloud resources:
    You will use Cloud Shell commands to create the BigQuery dataset and table, and the Bigtable instance and table.
    3. Create the Pub/Sub Topic and Subscription:
    You will use the Pub/Sub console to create the topic and subscription, and modify the subscription so that it can write to your BigQuery dataset and table.
    4. Grant Pub/Sub IAM permissions:
    You will use the IAM console to grant permissions to the compute service account.
    5. Retrieve the Python files from the repo:
    In this task, you retrieve the Python files from the repo, and configure the message_generator.py file for your project.
    6. Generate synthetic data
    With the file modified, you will then run the file. The file uses Python to generate continuous Pub/Sub messages for player chat.
    7. Create the BigQuery ML Remote Model:
    . In this task, you create an Agent Platform remote model connection to Gemini with a service account, and then use it to build your model in BigQuery.
    8. Run a continuous query to analyze chat messages:
    Now that you have sent the data to your Pub/Sub topic, your data is being captured and stored in your BigQuery table. You will run a query on the table to confirm messages are stored. Once you have confirmation the data is stored, you will create a continuous query in BigQuery using Gemini-based model to analyze each chat message as unsportsmanlike or sportsmanlike. You will then use a separate continuous query to send the unsportsmanlike chats to Bigtable.
    9. Monitor messages with your Streamlit application:
    Now that the unsportsmanlike messages are filtered and sent to Bigtable, you will use your Streamlit application to monitor the messages and take action.

    Task 8. Run a continuous query to analyze chat messages

    In this task you will run a continuous query to analyze the raw chat messages for unsportsman-like content. First you will confirm the raw_chat_messages table is updated with new messages from the Pub/Sub subscription with a query. Then you will generate the unsportsmanlike_messages table with the unsportsmanlike messages using a continuous query and Gemini, and then query it. Finally, you will export the unsportsmanlike messages to Bigtable.

    Query the raw_chat_messages table

    1. Return to BigQuery.

    2. In the explorer panel, find and select the raw_chat_messages table.

    3. Click Query. A template query is provided to you.

    4. Modify this query by selecting all records in the raw_chat_messages table, by using the query below:

      SELECT * FROM `{{{project_0.project_id|set at lab start}}}.esports_analytics.raw_chat_messages` LIMIT 1000

    5. Run the query. If you see records displayed, this means that Pub/Sub is updating the table with the latest messages (chat messages) from the generator.

    Insert the filtered messages into the unsportsmanlike_messages table

    1. In the explorer, expand your project and select the esports_analytics dataset.

    2. Click the plus to create a new query.

    3. In the query tab provided, enter the following query.

      INSERT INTO `esports_analytics.unsportsmanlike_messages` (message_id, user_id, timestamp, message_text, message_type, game_id, server_region) SELECT message_id, user_id, timestamp, message_text, ml_generate_text_llm_result AS category, game_id, server_region FROM ML.GENERATE_TEXT( MODEL `esports_analytics.gemini_model`, ( SELECT *, CONCAT( "You are an expert content moderator for an online competitive game. Your task is to classify the following chat message as either 'sportsmanlike' or 'unsportsmanlike'.", "\n\n", "An 'unsportsmanlike' message falls into one of these categories:", "\n- personal_harassment: Insults, threats, or attacks directed at another player.", "\n- spamming: Repetitive, irrelevant, or unsolicited messages.", "\n- promoting_cheating: Advertising or encouraging the use of cheats, hacks, or exploits.", "\n- impersonation: Falsely pretending to be another player, admin, or staff member.", "\n\n", "Here are some examples:", "\nMessage: 'EZ clap, you guys are trash uninstall the game.' -> unsportsmanlike", "\nMessage: 'get my aimbot for free at supercheats dot com!' -> unsportsmanlike", "\nMessage: 'ggwp, that was a really close match!' -> sportsmanlike", "\n\n", "Based on these definitions and examples, classify the following message. Respond with *only* the single word: 'sportsmanlike' or 'unsportsmanlike'.", "\n\nMessage: ", message_text ) AS prompt FROM APPENDS(TABLE `esports_analytics.raw_chat_messages`) ), STRUCT( 2048 AS max_output_tokens, 0.2 AS temperature, 1 AS candidate_count, TRUE AS flatten_json_output ) ) WHERE ml_generate_text_llm_result = 'unsportsmanlike'; Note: Notice how we are using the Appends Table Value Function. BigQuery continuous queries are designed to process new data as it arrives. To do this efficiently and reliably, they don't simply scan the entire source table (raw_chat_messages) repeatedly. APPENDS Table Value Function is a special function that allows continuous queries to only read newly appended rows to a source table since the last time the query ran. This is crucial for performance and ensuring the query processes only relevant incremental data.

      This query also filters out all the records with unsportsmanlike messages from the raw_chat_messages table and stores them in a new table called unsportsmanlike_messages.

    4. Click Edit.

    5. Select the Continuous query mode option and click Confirm.

    6. Run the query. Notice how it is now running continuously.

      Wait for 1 to 2 minutes before proceeding to the next step. On the Execution Details tab, you see the stages section of the Job update with S00: Input, S01: Compute and S02: Output included in the list. This means that your continuous query has processed records from the raw_chat_messages table and placed the results in the unsportsmanlike_messages table.

    Query the unsportsmanlike_messages table

    1. In the explorer, expand your project and select the esports_analytics dataset.

    2. Click the plus to create a new query.

    3. In the query tab provided, enter the following query.

      SELECT * FROM `{{{project_0.project_id|set at lab start}}}.esports_analytics.unsportsmanlike_messages` LIMIT 1000

    4. Run the query. This time you see only the unsportsmanlike_messages displayed.

    Create the EXPORT DATA to Bigtable continuous query

    1. Click the plus to create a new query.

    2. In the query tab provided, enter the following query.

      EXPORT DATA OPTIONS ( format = 'CLOUD_BIGTABLE', auto_create_column_families=TRUE, uri = 'https://bigtable.googleapis.com/projects/{{{project_0.project_id|set at lab start}}}/instances/instance/tables/unsportsmanlike' ) AS SELECT user_id AS rowkey, message_text, timestamp FROM APPENDS(TABLE `esports_analytics.unsportsmanlike_messages`)

    3. Click Edit.

    4. Choose the Continuous query mode option.

    5. Run the query.

      You will see an error like the one below:

      Bigtable app profile must be configured with LOW priority to run the export job. Current app profile: 'default' has priority: 'PRIORITY_HIGH'. Please refer to https://cloud.google.com/bigtable/docs/request-priorities on how to configure the app profile priority.

    You can resolve this error with the steps below.

    Set the Bigtable application profile to low

    1. Search for and access Bigtable at the top of the console.

    2. Click on the Instance ID, on the Bigtable Overview page, choose Application Profiles. The default application profile is displayed.

    3. Choose Edit Application Profile. Click the Edit application profile pencil within the default Application profile ID.

    4. For Select a routing priority, choose Low.

    5. Click Save.

    6. Return to BigQuery on the Query tab for EXPORT DATA.

    7. Run the query.

      You see the time running for the query. It will run indefinitely as it is continuous.

    Check the records processed by the EXPORT DATA Continuously running query

    1. Below the query, you see Job information and two tabs, Execution details and Execution Graph. The active tab is Execution details. Wait 1 to 2 minutes for the stages column to update with the first stage and click Execution Graph.

      The result is that you see the number of records currently processed.

      This means records are pulled from the unsportsmanlike_messages table in BigQuery and stored in the Bigtable table messages within your instance.

      Alternatively you can use the cbt Cloud Shell command below to query the unsportsmanlike table in Bigtable.

      cbt -instance instance read unsportsmanlike count=10

    If you see records displayed without an error message in Cloud Shell, this confirms the continuous query to write the records to Bigtable is working.

    Task 9. Monitor messages with your streamlit application

    In this task, you will access Cloud Shell, create and activate a Python 3 virtual environment, and then edit and run your app.py file. This will allow you to experience moderating unsportsmanlike messages, now that Bigtable has been populated with unsportsmanlike chat message records.

    Review app.py for your project

    1. Return to Cloud Shell terminal.

    2. Confirm you are in the home directory.

      cd ~

    3. Navigate to the esports directory.

      cd esports

    4. Open the Cloud Shell Editor.

    5. Open the app.py file.

    6. Review the file.

      At a high level the Python script app.py is a web application built using the Streamlit framework. Its primary purpose is to serve as a moderation dashboard for an esports platform. The application connects to a Google Cloud Bigtable database, fetches chat messages that have been flagged for "unsportsmanlike" conduct, and displays them in an interactive interface for a human moderator to review and take action on.

    Run your application

    1. Run the following command to run and deploy the application.

      streamlit run app.py \ --browser.serverAddress=localhost \ --server.enableCORS=false \ --server.enableXsrfProtection=false \ --server.port 8080

    Collecting usage statistics. To deactivate, set browser.gatherUsageStats to false. You can now view your Streamlit app in your browser. URL: http://localhost:8080

    This means that the application is now loaded.

    1. Click URL http://localhost:8080 to access the application and moderate the chat messages. Feel free to experiment with the application including testing the Suspend User, Ban User, and Dismiss as False Positive features.
